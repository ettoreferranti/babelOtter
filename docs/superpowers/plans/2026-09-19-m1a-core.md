# M1a Core — Text Processing & Configuration Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the pure, deterministic half of the M1a pipeline — configuration, text preparation, prompt composition and response parsing — so that the translation path exists and is provable before any Accessibility or networking code is written.

**Architecture:** Everything here is a value type or a pure function over values. No I/O except `ConfigurationStore`, which reads and writes one JSON file through the existing `StorageLocator`. Language detection is the one system-framework dependency (`NaturalLanguage`); its confidence policy is separated from the recognizer behind a protocol so the policy is deterministic and mutation-testable while the framework gets thin smoke tests. This means the entire milestone runs in CI on every push, with no simulator, no window server and no Ollama.

**Tech Stack:** Swift 6, swift-testing (`import Testing`), SPM, `NaturalLanguage`. No third-party dependencies — see `Config/dependency-allowlist.txt`, which is deliberately empty.

**Spec:** `docs/superpowers/specs/2026-09-18-babelotter-design.md` — binding authority. `docs/architecture.md` §7 is measured reality and supersedes §2–3 where they disagree.

## Global Constraints

- **NFR-P1 — no user content leaves the machine.** Nothing in this plan opens a socket. The networking guard (`NetworkingCallSiteTests`) permits exactly one file, `Sources/BabelOtterKit/LLM/OllamaClient.swift`, which this plan does not create.
- **NFR-Q3 — the core imports no UI framework.** `AppKit`, `SwiftUI`, `UIKit`, `Cocoa` and `Carbon` are banned in `BabelOtterKit` and enforced by `NoUIImportsTests`. `NaturalLanguage` and `Foundation` are permitted.
- **NFR-P6 — zero runtime dependencies.** Adding one requires an entry in `Config/dependency-allowlist.txt`. This plan adds none.
- **Mutation score ≥ 80%** for `BabelOtterKit`, gated in CI. Every new file under `Sources/BabelOtterKit` **must** be assigned to pass 1 or pass 2 of the mutation file list in `.github/workflows/ci.yml`, or the build fails by design.
- **User content is unloggable without redaction** — `UserText` (NFR-P3). Any type holding selection text or model output wraps it in `UserText` or is never logged.
- **de-CH means `ß` never appears in output** (`FR-TRN-05`).
- **Swift 6 strict concurrency.** Every public value type is `Sendable`.
- **Verify guards by making them fail.** A green suite is not evidence. Twelve times during M0 a guard shipped that looked protective and was not. Every invariant below has a test that was watched failing before the implementation existed.

### Task 1: Languages and locale rules as data (#56)

**Files:**
- Create: `Sources/BabelOtterKit/Config/LanguageConfig.swift`
- Test: `Tests/BabelOtterKitTests/Config/LanguageConfigTests.swift`

**Interfaces:**
- Consumes: nothing.
- Produces:
  - `struct LanguageCode: Sendable, Hashable, Codable, RawRepresentable { init(_ raw: String); var rawValue: String }` — case-insensitive on init, stored lowercased.
  - `struct LocaleRule: Sendable, Equatable, Codable { let replace: String; let with: String }`
  - `struct LanguageConfig: Sendable, Equatable, Codable { let code: LanguageCode; let displayName: String; let localeRules: [LocaleRule]; var enabled: Bool }`
  - `extension LanguageConfig { static let english: LanguageConfig; static let swissGerman: LanguageConfig; static let shippedDefaults: [LanguageConfig] }`

**Design notes:**

`LocaleRule` is plain data — a literal `replace`/`with` pair, applied in array order. It is deliberately *not* a regex: `FR-LNG-02` wants rules attachable by configuration, and a regex in a hand-edited config file is a foot-gun that can also be made to backtrack catastrophically on user text. `de-CH` ships exactly one rule, `ß` → `ss`.

`LanguageCode` lowercases on construction so `"DE-CH"` and `"de-CH"` are the same key. This matters because config files are hand-edited (`FR-CFG-03`).

### Task 3: Glossary, configuration root and persistence (#55, #59 model, #60)

**Files:**
- Create: `Sources/BabelOtterKit/Config/Glossary.swift`
- Create: `Sources/BabelOtterKit/Config/Configuration.swift`
- Create: `Sources/BabelOtterKit/Config/ConfigurationStore.swift`
- Test: `Tests/BabelOtterKitTests/Config/GlossaryTests.swift`

**Interfaces:**
- Consumes: `LanguageConfig`, `LanguageCode` (Task 1); `AudienceProfile` (Task 2); `StorageLocator` (existing, M0).
- Produces:
  - `struct LanguagePair: Sendable, Hashable, Codable { let source: LanguageCode; let target: LanguageCode }`
  - `struct GlossaryEntry: Sendable, Equatable, Codable { let source: String; let target: String; let pair: LanguagePair }`
  - `struct Glossary: Sendable, Equatable, Codable { var entries: [GlossaryEntry]; func entries(for pair: LanguagePair) -> [GlossaryEntry] }`
  - `enum Action: String, Sendable, Codable, CaseIterable { case translate, correct, explain, repitch }`
  - `struct Configuration: Sendable, Equatable, Codable` with `languages`, `profiles`, `glossary`, `doNotTranslate: [String]`, `models: [Action: String]`, `timeoutSeconds: Double`, `retentionDays: Int`, `detectionConfidenceFloor: Double`, `minimumLengthForDetection: Int`, and `static let `default``.
  - `struct ConfigurationStore` with `init(directory: URL)`, `func load() -> (configuration: Configuration, problems: [ConfigurationProblem])`, `func save(_:) throws`.
  - `struct ConfigurationProblem: Sendable, Equatable { let file: String; let field: String?; let detail: String }`

**Design notes:**

`load()` **never throws and never crashes** (`FR-CFG-03` acceptance: a malformed file names the file and field, and defaults are used). It returns defaults plus a `problems` array the UI can surface later. A `DecodingError`'s `codingPath` gives the field name; that mapping is the mutation-interesting part.

`save` writes with `.prettyPrinted` **and** `.sortedKeys` so a hand-edited file produces a stable diff (`FR-CFG-03`).

`Glossary.entries(for:)` filters by exact pair — `FR-GLO-01` is bidirectional, so a caller wanting both directions asks twice. Filtering in the model keeps `PromptBuilder` (Task 12) from including irrelevant entries.

`models: [Action: String]` gives `FR-CFG-02` a different model per action. `Action` lives here rather than in the LLM layer because configuration is what enumerates it.

### Task 4: Structure extraction with a byte-identical round trip (#37)

**Files:**
- Create: `Sources/BabelOtterKit/Text/StructureExtractor.swift`
- Test: `Tests/BabelOtterKitTests/Text/StructureExtractorTests.swift`

**Interfaces:**
- Consumes: nothing.
- Produces:
  - `struct Skeleton: Sendable, Equatable` — opaque line record; `var blockCount: Int`
  - `struct ExtractedText: Sendable, Equatable { let skeleton: Skeleton; let blocks: [String] }`
  - `enum StructureExtractor { static func extract(_ text: String) -> ExtractedText; static func reapply(_ blocks: [String], to skeleton: Skeleton) throws -> String }`
  - `enum StructureError: Error, Equatable { case blockCountMismatch(expected: Int, received: Int) }`

**Design notes:**

This is the file the spec names first among mutation targets, because block-index arithmetic silently scrambles a user's paragraphs when it is wrong.

Each source line is decomposed into four parts that concatenate back to the original **exactly**: `indent` (leading whitespace) + `marker` (list marker including its trailing space, or empty) + `prose` + `terminator` (`"\r\n"`, `"\n"`, `"\r"`, or `""` on a final line with no newline). Storing the terminator *per line* rather than detecting one style for the document is what makes mixed endings and a missing trailing newline round-trip byte-identically.

Only lines with non-empty `prose` contribute a block. `blockIndex` is stored on the line, so `reapply` never has to recount — the off-by-one lives in exactly one place, at extraction, where a test can pin it.

Recognised markers, anchored at the start of the trimmed line: `- `, `* `, `+ `, `1. ` (any digits), `a) ` (single letter). A marker is only a marker when followed by a space, so `-5 degrees` is prose.

`reapply` throws on a count mismatch rather than truncating or padding: silent structure corruption is the failure mode this whole type exists to prevent. Task 14 turns that error into the retry policy.

```swift
import Testing
@testable import BabelOtterKit

@Suite("Structure survives the round trip")
struct StructureExtractorTests {

    /// The property that matters: extracting and re-applying unchanged blocks is
    /// the identity function, for every shape of input we claim to support.
    @Test("extract then re-apply unchanged is byte-identical", arguments: [
        "Hello world.",
        "First paragraph.\n\nSecond paragraph.",
        "- one\n- two\n- three",
        "1. one\n2. two",
        "a) alpha\nb) beta",
        "    indented\n        more indented",
        "crlf line one\r\ncrlf line two\r\n",
        "mixed\r\nendings\nhere",
        "trailing whitespace   \nand a final newline\n",
        "no trailing newline",
        "\n\n\n",
        "",
        "  - indented bullet\n  - another",
        "-5 degrees is prose, not a bullet",
    ])
    func roundTripIsIdentity(_ input: String) throws {
        let extracted = StructureExtractor.extract(input)
        #expect(try StructureExtractor.reapply(extracted.blocks, to: extracted.skeleton) == input)
    }

    @Test("list markers are preserved and never sent to the model as prose")
    func markersAreNotProse() {
        let extracted = StructureExtractor.extract("- one\n- two")
        #expect(extracted.blocks == ["one", "two"])
    }

    @Test("numbered and lettered markers are not prose either")
    func numberedMarkers() {
        #expect(StructureExtractor.extract("1. one\n2. two").blocks == ["one", "two"])
        #expect(StructureExtractor.extract("a) alpha\nb) beta").blocks == ["alpha", "beta"])
    }

    @Test("a hyphen not followed by a space is prose")
    func hyphenIsNotAlwaysAMarker() {
        #expect(StructureExtractor.extract("-5 degrees").blocks == ["-5 degrees"])
    }

    @Test("indentation is preserved per line")
    func indentationPreserved() throws {
        let input = "    four\n        eight"
        let extracted = StructureExtractor.extract(input)
        #expect(extracted.blocks == ["four", "eight"])
        #expect(try StructureExtractor.reapply(["vier", "acht"], to: extracted.skeleton) == "    vier\n        acht")
    }

    @Test("blank lines produce no blocks")
    func blankLinesAreNotBlocks() {
        #expect(StructureExtractor.extract("one\n\n\ntwo").blocks == ["one", "two"])
    }

    @Test("translated blocks land in the right slots")
    func blocksLandInOrder() throws {
        let extracted = StructureExtractor.extract("- one\n\n- two")
        #expect(try StructureExtractor.reapply(["eins", "zwei"], to: extracted.skeleton) == "- eins\n\n- zwei")
    }

    @Test("too few blocks is an error, never a silent truncation")
    func tooFewBlocks() {
        let extracted = StructureExtractor.extract("one\ntwo")
        #expect(throws: StructureError.blockCountMismatch(expected: 2, received: 1)) {
            try StructureExtractor.reapply(["eins"], to: extracted.skeleton)
        }
    }

    @Test("too many blocks is an error too")
    func tooManyBlocks() {
        let extracted = StructureExtractor.extract("one")
        #expect(throws: StructureError.blockCountMismatch(expected: 1, received: 2)) {
            try StructureExtractor.reapply(["eins", "zwei"], to: extracted.skeleton)
        }
    }

    @Test("blockCount agrees with the number of blocks produced")
    func blockCountAgrees() {
        let extracted = StructureExtractor.extract("- one\n\n- two\n- three")
        #expect(extracted.skeleton.blockCount == extracted.blocks.count)
        #expect(extracted.skeleton.blockCount == 3)
    }
}
```

### Task 5: Do-not-translate masking and restoration (#38)

**Files:**
- Create: `Sources/BabelOtterKit/Text/TokenProtector.swift`
- Test: `Tests/BabelOtterKitTests/Text/TokenProtectorTests.swift`

**Interfaces:**
- Consumes: nothing.
- Produces:
  - `struct ProtectedText: Sendable, Equatable { let text: String; let terms: [String] }` — `terms[i]` is the term behind sentinel `i`
  - `struct RestoredText: Sendable, Equatable { let text: String; let protectedRanges: [Range<String.Index>]; let problems: [ProtectionProblem] }`
  - `enum ProtectionProblem: Sendable, Equatable { case sentinelMissing(index: Int, term: String); case sentinelDebris(String) }`
  - `enum TokenProtector { static func mask(_ text: String, terms: [String]) -> ProtectedText; static func restore(_ text: String, from protected: ProtectedText) -> RestoredText }`

**Design notes:**

Sentinel format is `⟦DNT0⟧` — corner brackets chosen because they are outside any Latin or German keyboard's reach, so they cannot appear in the user's own writing, and because a local model is unlikely to "helpfully" translate them.

**Longest match wins:** terms are sorted by length descending before masking, so `"ZHAW School of Engineering"` masks as one unit rather than leaving `"School of Engineering"` exposed after `"ZHAW"` matched.

**Word boundaries:** a term only matches when the characters immediately before and after are not alphanumeric. Without this, `"IT"` inside `"Item"` becomes a sentinel and the user's prose is destroyed. Boundary detection uses `Character.isLetter || Character.isNumber`, which is Unicode-correct for German umlauts — an ASCII-only check would treat `ä` as a boundary and mask the `IT` in `"ITär"`.

**Matching is case-sensitive.** DNT terms are proper nouns and product names, where case is part of the identity. `→ Open question for the user, recorded in the handoff.`

`restore` reports rather than repairs. A model that mangles `⟦DNT3⟧` into `⟦ DNT3 ⟧` produces `sentinelMissing`; any residual `⟦DNT` substring after restoration produces `sentinelDebris`. Leaving sentinel debris in output the user pastes into an email is the failure this reporting exists to prevent.

`protectedRanges` are in **restored-text coordinates** and are what Task 6 must not rewrite. They can only be computed during restoration, which is precisely why §8 fixes this order.

- [ ] **Step 1: Write the failing tests**

Cases, each its own `@Test`:
1. `mask("ZHAW is here", terms: ["ZHAW"])` → text `"⟦DNT0⟧ is here"`, terms `["ZHAW"]`.
2. Every occurrence is masked: `"ZHAW and ZHAW"` → `"⟦DNT0⟧ and ⟦DNT0⟧"` (one index per *term*, reused — restoration is by term, not by occurrence).
3. Round trip: `restore(mask(t).text, from: mask(t)).text == t` for a table of inputs.
4. Longest match wins: terms `["ZHAW", "ZHAW School"]` against `"ZHAW School rules"` masks the longer, leaving no bare `"School"`.
5. Inside a longer word is not masked: terms `["IT"]` against `"Item"` → unchanged, no sentinel.
6. Umlaut boundary: terms `["IT"]` against `"ITär"` → unchanged (proves the Unicode boundary check).
7. Missing sentinel reported: restoring `"the model ate it"` from a mask that had one term → `problems == [.sentinelMissing(index: 0, term: "ZHAW")]`.
8. Debris reported: restoring `"⟦DNT7⟧ leftover"` where only index 0 exists → a `.sentinelDebris` problem.
9. Restored ranges point at the restored terms: `restore` of `"⟦DNT0⟧ ist gross"` gives one range whose slice equals `"ZHAW"`.
10. No terms is a no-op with no problems.

### Task 7: The §8 post-processing order (#39)

**Files:**
- Create: `Sources/BabelOtterKit/Text/PostProcessor.swift`
- Test: `Tests/BabelOtterKitTests/Text/PostProcessorTests.swift`

**Interfaces:**
- Consumes: Tasks 1, 5, 6.
- Produces: `struct PostProcessor { let rules: [LocaleRule]; func finish(_ modelOutput: String, protected: ProtectedText) -> (text: String, problems: [ProtectionProblem]) }`

**Design notes:**

This type exists only to fix the order §8 mandates: **restore sentinels first, then apply locale rules to everything except the restored spans.**

The order is load-bearing for a reason worth stating precisely, because it is easy to talk yourself out of. Restoring first is what *produces* `protectedRanges` in the coordinates the applier needs. Applying rules first and restoring afterwards would also preserve a DNT term's `ß` — the two orders agree on that case — but it cannot protect anything, because at that point there is nothing to protect: the spans do not exist yet. So the invariant the tests pin is not merely "restore is called first" but "the ranges handed to the applier are the ones restoration produced".

### Task 8: Language detection with a confidence floor (#36)

**Files:**
- Create: `Sources/BabelOtterKit/Text/LanguageDetector.swift`
- Test: `Tests/BabelOtterKitTests/Text/LanguageDetectorTests.swift`

**Interfaces:**
- Consumes: `LanguageCode` (Task 1).
- Produces:
  - `protocol LanguageRecognizing: Sendable { func hypotheses(for text: String) -> [LanguageCode: Double] }`
  - `struct NaturalLanguageRecognizer: LanguageRecognizing` — wraps `NLLanguageRecognizer`
  - `enum Detection: Sendable, Equatable { case confident(LanguageCode, confidence: Double); case ambiguous(AmbiguityReason) }`
  - `enum AmbiguityReason: Sendable, Equatable { case tooShort(length: Int, minimum: Int); case belowFloor(best: LanguageCode, confidence: Double, floor: Double); case noHypothesis }`
  - `struct LanguageDetector: Sendable { init(recognizer: any LanguageRecognizing, floor: Double, minimumLength: Int); func detect(_ text: String) -> Detection }`

**Design notes:**

The recognizer sits behind a protocol for one reason: `NLLanguageRecognizer` is a system ML model whose exact confidences vary by OS version, and this project runs two majors apart locally and in CI. Asserting `0.83 > floor` against a live model would produce a test that passes on one machine and fails on the other. The *policy* — floor comparison, length check, tie-breaking — is what must be deterministic and mutation-killable, so it is tested against a stub. The framework itself gets two smoke tests over unambiguous sentences, asserting only which language wins.

Length is measured in **non-whitespace characters**, so `"   hi   "` is length 2. A whitespace-padded selection is exactly the short-selection case `FR-TRN-03` means.

The floor comparison is `>=`: a confidence exactly at the configured floor is confident. Stated because a mutant flipping it to `>` must be killed by a test sitting precisely on the boundary.

- [ ] **Step 1: Write the failing tests**

Policy tests against a `StubRecognizer` returning fixed hypotheses:
1. Above the floor → `.confident`.
2. Exactly at the floor → `.confident` (boundary, kills `>` vs `>=`).
3. Just below the floor → `.ambiguous(.belowFloor(...))` carrying the best guess.
4. Text shorter than the minimum → `.ambiguous(.tooShort(...))`, and the recognizer is **never consulted** (assert with a recording stub).
5. Whitespace-only text → `.tooShort` with length 0.
6. Length counts non-whitespace only: `"   hi   "` with minimum 3 → `.tooShort(length: 2, minimum: 3)`.
7. No hypotheses at all → `.ambiguous(.noHypothesis)`.
8. Highest confidence wins when several hypotheses are returned.

Framework smoke tests, `@Test` each:
9. A long, plainly English paragraph detects as `en`.
10. A long, plainly German paragraph detects as `de`.

### Task 13: Block-count validation and the single retry (#44)

**Files:**
- Create: `Sources/BabelOtterKit/LLM/BlockCountPolicy.swift`
- Test: `Tests/BabelOtterKitTests/LLM/BlockCountPolicyTests.swift`

**Interfaces:**
- Consumes: Task 4 (`StructureError`).
- Produces:
  - `enum BlockCountDecision: Sendable, Equatable { case accept; case retryWholeText; case degrade(reason: String) }`
  - `struct BlockCountPolicy: Sendable { func decide(expected: Int, received: Int, attempt: Int) -> BlockCountDecision }`

**Design notes:**

A pure function of `(expected, received, attempt)` rather than a stateful retrier, so "no more than one retry is ever issued" is a property provable by exhaustion instead of by inspection. The caller owns the attempt counter; the policy owns the rule.

`attempt` is zero-based: `0` is the first response, `1` is the response to the single retry. At `attempt >= 1` a mismatch degrades and never retries again.

The `degrade` case carries a reason string destined for the user, because `FR-CAP-05` and `NFR-REL-2` both require telling the user structure could not be preserved rather than quietly returning scrambled paragraphs.
